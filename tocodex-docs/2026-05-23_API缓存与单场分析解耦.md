# API 缓存与单场分析解耦

## 摘要

本次针对 `football-intel-api` 请求过慢的问题，增加了进程内轻量 TTL/LRU 缓存，并调整了比赛列表获取与单场分析接口的调用边界：

- 新增进程级 `TTLCache`，用于短时间复用外部 API/爬虫结果。
- 在聚合层缓存比赛列表、Match ID 基础信息、单场快照、单源赔率结果。
- 单场分析接口不再主动刷新全量比赛列表，只读取已有 Match ID 缓存；未命中时直接按单场快照惰性加载。
- 聚合单场快照时复用 provider snapshot 已带的赔率，减少同一次请求内的重复赔率抓取。
- 新增 `/cache/stats` 端点，便于观察缓存命中、未命中和淘汰情况。

## 变更文件

- `app/services/cache.py`
  - 新增 `TTLCache` 与 `CacheStats`。
  - 支持 TTL 过期、LRU 淘汰、线程锁和 deepcopy 防止缓存对象被调用方污染。

- `app/services/aggregator.py`
  - 新增进程级缓存：`match_lists`、`match_refs`、`match_snapshots`、`provider_odds`。
  - `get_upcoming_matches()` 增加列表缓存，并同步填充 Match ID 缓存。
  - `get_match_snapshot()` 增加快照缓存和单源赔率缓存。
  - 新增 `get_cached_match_ref()` 只读缓存方法，用于避免单场分析触发全量赛程刷新。
  - 新增 `cache_stats()` 返回缓存统计。

- `app/routes/predict.py`
  - `/match/{match_id}/analysis` 不再调用 `get_upcoming_matches()` 拉取全量比赛。
  - 改为只读取 `aggregator.get_cached_match_ref(match_id)`，未命中不触发额外列表请求。

- `app/main.py`
  - 新增 `/cache/stats` 端点，返回缓存状态。

